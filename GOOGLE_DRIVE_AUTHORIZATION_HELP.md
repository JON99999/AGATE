# Google Drive Authorization & Connection Guide (Interstitial-er)

This guide provides step-by-step instructions on how the three different authentication options work in **Interstitial-er**, how to obtain the necessary credentials, and how to configure them for standard desktop or restricted corporate environments.

---

## 🧭 Understanding the 3 Connection Methods

Interstitial-er offers three distinct techniques to link your application with Google Drive so it can synchronize scheduler listings, MP3 audio libraries, and log databases:

### Option 1: Autopilot (Desktop Browser Loopback) — *RECOMMENDED DEFAULT*
* **How it works:** This is the default, primary option. When you click **Connect**, Interstitial-er launches your system's default web browser. Once you log in and authorize Google Drive access, the browser redirects back to an embedded loopback endpoint on your locally running Express server (`http://127.0.0.1:3000/api/oauth-callback`). The app automatically intercepts this secure token, starts the authenticated session, and closes the browser tab.
* **Best for:** Standard operations, Apple Silicon / Intel Macs, and Windows PCs.
* **Requirements:** A valid Client ID configured for Desktop environments that whitelists loopback callbacks (default pre-packaged ID works out of the box).

### Option 2: Browser Verification with Copy-Paste (Failsafe)
* **How it works:** This is an absolute failsafe method. It processes logins using the exact same OAuth setup, but bypasses the automatic loopback listener network channel. When you click **Get Token from Browser**, you will authorize in your browser. Upon redirect, the webpage secure local layout prints the temporary access token directly onto the screen. Copy that token, paste it into the Interstitial-er access box, and click **Apply**.
* **Best for:** Machines with strict firewalls, corporate intranets, sandboxed operating systems, or ports blocking loopback (`127.0.0.1`) communication.

### Option 3: Direct Manual Access Token (Developer Bypass)
* **How it works:** Instant, direct token injection. This bypasses the browser redirections entirely. You can input any active, valid temporary Google Access Token (Bearer token) generated by an external developer console or testing toolkit (such as the Google OAuth Playground).
* **Best for:** System developers, script tasks, network debugging, or running immediate diagnostic checks.
* **Limitations:** Manual tokens expire in 60 minutes.

## 🛠️ Step-by-Step Google Cloud Project (Custom Client ID) Setup

Your Interstitial-er app comes pre-packaged with a default Client ID. However, for dedicated enterprise stability or if you run into whitelisted testing limits, you should generate your own Google Cloud Client ID.

### Step 1: Create your GCP Project & Enable APIs
1. Navigate directly to the [Google Cloud Console](https://console.cloud.google.com/).
2. Create a new project (e.g., `Interstitialer-Scheduler`).
3. Enable the Google Drive API:
   * Go to the API library page: [https://console.cloud.google.com/apis/library/browse?project=interstitial-er](https://console.cloud.google.com/apis/library/browse?project=interstitial-er) *(Ensure your active project is selected in the console header dropdown)*.
   * Search for **Google Drive API** and click **Enable**.

### Step 2: Configure the OAuth Consent Screen
Since you are deploying this as a desktop environment, define who can authorize access.
1. Click **APIs & Services** > **OAuth consent screen** ([Consent Screen Link](https://console.cloud.google.com/apis/credentials/consent)).
2. Select **External** and click **Create**.
3. Input basic details: Set App Name to `Interstitial-er`, and insert your email address as the developer/support contact.
4. Click **Save and Continue** to navigate to the **Test Users** screen.

### Step 3: Authorizing Test Email Addresses
By default, custom Google Cloud projects exist in "Testing Mode." Google blocks log-ins from any account that is not explicitly whitelisted.
1. Scroll down to the **Test users** section on the consent page: [https://console.cloud.google.com/apis/credentials/consent](https://console.cloud.google.com/apis/credentials/consent).
2. Click **+ ADD USERS**.
3. Enter your personal Gmail or organization Workspace accounts that need to authorize the app.
4. Click **Save**.

> ### 💡 Corporate Organization Deployment Tip
> To deploy across several broadcast terminals or automated players without managing many test emails or individual OAuth limits, we highly advise setting up **one dedicated functional email address or group account** (e.g., `broadcast-drive@company.org`).
> 
> 1. Grant this email read/write privileges to your Google Drive folders.
> 2. Whitelist only this simple email under **Test Users**.
> 3. Log into this account to authorize all your local player units.

### Step 4: Create Desktop OAuth Credentials
1. Under **APIs & Services**, click **Credentials** ([Credentials Link](https://console.cloud.google.com/apis/credentials)).
2. Click **+ CREATE CREDENTIALS** at the top, then select **OAuth client ID**.
3. Under **Application type**, choose **Desktop app**.
4. Name your client (e.g., `Interstitialer Player Client`).
5. Click **Create** and copy the resulting string under **Client ID** (ends with `.apps.googleusercontent.com`).

## 🏃 Setup Steps for Individual Options

### Setup Step: Option 1 (Autopilot)
1. Open Interstitial-er Settings, expand the **Advanced connection options**.
2. Paste your **Google OAuth Client ID** into the Option 1 Client ID field.
3. Click **Connect** (or *Launch Autopilot Login*).
4. Authorize the app in your browser window. Once finished, the tab will display a success message and close.

### Setup Step: Option 2 (Copy-Paste)
1. In Interstitial-er Settings, paste your **Client ID** under Option 2.
2. Click **1. Get Token from Browser**.
3. Log in. On the success screen, click **Copy** button on the page.
4. Return to Interstitial-er. Paste the token into the **Access Token** field under Option 2 and click **Apply**.

### Setup Step: Option 3 (Direct Token)
To test with Google's temporary Playground:
1. Navigate to the [Google OAuth Playground](https://developers.google.com/oauthplayground).
2. Under "Select & authorize APIs," enter `https://www.googleapis.com/auth/drive` into the input bar and click **Authorize APIs**.
3. Authorize via your account.
4. On step 2 in the playground, click **Exchange authorization code for tokens**.
5. Copy the **Access Token** value.
6. Open Interstitial-er, navigate to Option 3, paste the token, and click **Apply**.
